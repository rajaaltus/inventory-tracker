# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Team Asset Tracker — an internal tool for tracking hardware, software licenses, and equipment assigned to team members. Built with Next.js (App Router) + Convex backend + Convex Auth (password-based).

## Commands

```bash
pnpm dev              # Start both frontend (Next.js) and backend (Convex) concurrently
pnpm dev:frontend     # Start only Next.js dev server
pnpm dev:backend      # Start only Convex dev server
pnpm build            # Production build (Next.js)
pnpm lint             # ESLint (ignores convex/_generated)
```

The `predev` script runs `convex dev --once` and `node setup.mjs --once` before dev starts — this syncs the Convex schema and generates keys.

## Architecture

**Frontend:** Next.js 16 App Router with React 19. Uses Tailwind CSS v4, shadcn/ui (radix-nova style), and Recharts for charts. Theme support via next-themes.

**Backend:** Convex (serverless backend-as-a-service). Convex functions live in `src/convex/` (configured via `convex.json`). The `src/convex/_generated/` directory is auto-generated — never edit it.

**Auth:** Convex Auth with Password provider. Middleware in `middleware.ts` protects `/dashboard` and `/server` routes, redirecting unauthenticated users to `/signin`. Authenticated users on `/signin` redirect to `/dashboard`.

**Provider hierarchy** (in `app/layout.tsx`):
`ConvexAuthNextjsServerProvider` → `ThemeProvider` → `ConvexClientProvider` (client-side Convex + auth)

## Key Conventions

- **Path alias:** `@/*` maps to the project root (e.g., `@/components/ui/button`)
- **Convex functions directory:** `src/convex/` (not the default `convex/`)
- **shadcn/ui config:** `components.json` — style is "radix-nova", components go in `components/ui/`, utils in `lib/utils.ts`
- **Package manager:** pnpm
- **UI components:** Add via `pnpm dlx shadcn@latest add <component>`

## Convex Guidelines

Convex functions use validators (`v` from `convex/values`) for all arguments. Use `query`/`mutation`/`action` for public functions, `internalQuery`/`internalMutation`/`internalAction` for private ones. Function references use the `api` or `internal` objects from `_generated` — never pass functions directly to `ctx.runQuery`/`ctx.runMutation`. Full Convex coding guidelines are in `.cursor/rules/convex_rules.mdc`.

## Environment Variables

See `.env.example`. The key variable is `CONVEX_DEPLOY_KEY` (for production). Dev uses `NEXT_PUBLIC_CONVEX_URL` (auto-configured by Convex CLI) and auth-related keys generated by `setup.mjs`/`generateKeys.mjs`.
